<h1 align="center">Jtagram</h1>

## ¿Qué es Jtagram?

**Jtagram es un ecosistema para gestionar y organizar el entorno de desarrollo de software de una empresa.**

Su objetivo es ayudar a las empresas a trabajar de manera ordenada desde el comienzo, mediante procesos definidos, algunos automatizados y otros manuales.

## 1. ¿Qué problema resuelve Jtagram?

Muchas empresas comienzan a desarrollar una aplicación de manera informal. Al principio, el equipo es pequeño y todos conocen lo que están haciendo. Sin embargo, a medida que la empresa crece, el desarrollo se vuelve más complejo y mantener el orden resulta cada vez más difícil.

Con el tiempo, puede ser complicado entender cómo funciona cada parte del sistema, dónde se encuentra la información o qué pasos hay que seguir para realizar una tarea.

Esto también genera una dependencia de las personas que desarrollaron originalmente el software. Por ejemplo, si un empleado se va de la empresa y gran parte del conocimiento está en su cabeza, la persona que lo reemplaza puede tener muchas dificultades para continuar el trabajo.

En algunos casos, la empresa termina dependiendo demasiado de determinados empleados porque teme perder el conocimiento que ellos poseen.

**Jtagram busca prevenir estos problemas desde el principio**, estableciendo una estructura de trabajo organizada, con procesos definidos y responsabilidades claras. De esta manera, resulta más fácil mantener el software, incorporar nuevos empleados y dar continuidad al desarrollo, incluso cuando cambian los integrantes del equipo.

## 2. ¿Qué es un entorno de desarrollo?

Para entenderlo, primero imaginemos la cocina de un restaurante.

Un chef necesita diferentes elementos para preparar sus platos: hornos, ollas, sartenes, cuchillos, heladeras y utensilios. Todos estos elementos forman parte de su entorno de trabajo.

Ahora imaginemos que cada vez que el chef necesita una sartén tiene que salir a buscarla, comprobar si está limpia, utilizarla, lavarla, secarla y guardarla para que pueda volver a utilizarse.

Todas esas tareas son necesarias, pero no forman parte directa de la preparación del plato. Son tareas relacionadas con la organización y el funcionamiento de su entorno de trabajo.

Si el restaurante cuenta con un sistema organizado, con procedimientos bien definidos y algunas tareas automatizadas, el chef puede concentrarse en cocinar. Por ejemplo, puede existir un proceso establecido para que los utensilios estén disponibles cuando se necesitan y para que, después de utilizarlos, queden limpios y preparados para el siguiente uso.

El chef sigue siendo responsable de preparar el plato, pero ya no necesita resolver por su cuenta cada detalle de la organización de la cocina.

## 3. ¿Qué tiene que ver esto con el desarrollo de software?

Desarrollar software es, en cierto sentido, como preparar un plato: hay que combinar diferentes elementos y seguir determinados pasos para obtener un resultado que funcione correctamente.

Pero, en lugar de utilizar hornos, ollas y cuchillos, los desarrolladores trabajan con servidores, herramientas de programación, sistemas de almacenamiento, bases de datos y otros componentes tecnológicos.

Todos estos elementos forman parte del entorno de desarrollo de software.

Para que el equipo pueda trabajar correctamente, no alcanza con tener las herramientas disponibles. También es necesario organizarlas, definir cómo se utilizan y establecer qué sucede antes, durante y después de cada tarea.

Por ejemplo, cuando un desarrollador necesita realizar un cambio en una aplicación, puede ser necesario preparar el entorno de trabajo, acceder a la información correspondiente, ejecutar determinadas herramientas, comprobar que los cambios funcionen y dejar todo preparado para continuar trabajando.

Si cada empleado realiza estas tareas de una manera diferente, el proceso se vuelve difícil de mantener y controlar.

## 4. ¿Cómo interviene Jtagram?

Jtagram busca gestionar ese entorno mediante un conjunto de procesos definidos, algunos automatizados y otros manuales.

Siguiendo el ejemplo de la cocina, sería como contar con un sistema que organiza los elementos y los procedimientos necesarios para que el chef pueda concentrarse en cocinar.

En el desarrollo de software, la idea es similar: **que los desarrolladores puedan concentrarse en crear y mejorar las aplicaciones, mientras el entorno de trabajo se gestiona siguiendo procedimientos establecidos.**

Esto permite que las tareas no dependan exclusivamente de la memoria, las costumbres o las decisiones individuales de cada empleado. En cambio, el equipo puede apoyarse en una estructura de trabajo compartida.

## 5. ¿Por qué es importante implementarlo desde el principio?

Organizar un entorno de desarrollo cuando una empresa ya lleva años trabajando de manera desordenada puede ser mucho más difícil que hacerlo desde el comienzo.

A medida que el software crece, también se acumulan herramientas, procedimientos informales, decisiones técnicas y conocimientos que pueden no estar documentados.

Corregir esa situación requiere tiempo y esfuerzo, y en algunos casos puede afectar la continuidad del desarrollo.

Jtagram propone abordar este problema de manera preventiva: establecer una organización desde las primeras etapas, para que el entorno pueda acompañar el crecimiento de la empresa.

## Alcance

Jtagram está pensado para **desarrollar aplicaciones personales en un home lab**: un servidor propio en casa, con sus máquinas virtuales, donde una sola persona o un equipo muy chico monta y opera todo el ecosistema. Ese es su alcance actual.

La misma estructura se puede **llevar a mayor escala**, por ejemplo en una empresa que recién comienza. Para eso habría que adaptar la infraestructura y robustecer la lógica, ya que acá está dimensionado para un entorno chico.

> [!WARNING]
> Jtagram está en **etapa de desarrollo**. La estructura, los procesos y la documentación pueden cambiar, y todavía no hay garantía de que esté listo para producción.

## En resumen

Jtagram es un ecosistema orientado a organizar y gestionar el entorno de desarrollo de software mediante procesos definidos, tanto manuales como automatizados.

Su propósito es ayudar a las empresas a desarrollar sus aplicaciones de manera más ordenada, reducir las dificultades operativas, facilitar la incorporación de nuevos integrantes al equipo y evitar que el conocimiento necesario para mantener el software quede concentrado en unas pocas personas.

La idea central es sencilla: **no se trata solamente de desarrollar aplicaciones, sino también de organizar el entorno y los procesos que permiten desarrollarlas y mantenerlas a lo largo del tiempo.**
